Built for local operational scripts.

CronBox behaves more like a small Windmill-style control surface than a generic cron editor. The primary object is the run history and the log, not decorative scheduling chrome.

01

Entrypoint scanning

Only scripts that can actually run are surfaced when you add a directory.

02

Menu bar runtime

Close the main window and scheduled jobs keep running from the menu bar process.

03

Live logs

stdout and stderr stream into job history while the process is still active.

04

Skip overlap

If the previous scheduled run is still queued or running, the next tick is skipped.

Schedule coding agents like any other script.

CronBox can create Codex and Claude Code task scripts under a default local workspace. That workspace carries durable rules files, so scheduled agent runs behave consistently.

Workspace Agent tasks run from ~/.cronbox by default.
Rules AGENTS.md and CLAUDE.md live beside the generated tasks.
History Each run keeps metadata, inputs, output, error, duration, and logs together.

Manage it from the app or terminal.

The desktop app installs a companion cronbox command when possible, so local automation can be scripted without opening the UI.

terminal
cronbox add ~/scripts
cronbox scripts list
cronbox schedules add ./daily-report.sh "0 9 * * *" --tz Asia/Shanghai
cronbox jobs list
cronbox run ~/scripts daily-report.sh --args '{"date":"today"}'

A compact loop for recurring local work.

CronBox keeps the operational path short: scan, schedule, watch logs, inspect history, adjust, repeat.

1

Add a directory

Point CronBox at a script folder. Non-runnable files stay out of the list.

2

Configure one dialog

Edit alias, cron expression, timezone, args, and enabled state in one place.

3

Read the log

Use the detail view as the source of truth for inputs, history, result, and output.
